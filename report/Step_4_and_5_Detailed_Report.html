SECTION 1: THEORETICAL FOUNDATIONS OF STANCE DETECTION

1.1 Theoretical Distinction: Stance Detection vs. Sentiment Analysis A frequent misconception in NLP is equating Stance Detection with Sentiment Analysis. They are mathematically and conceptually distinct tasks:
  • Sentiment Analysis models the subjective emotional polarity of the author (Positive, Negative, or Neutral) towards the general topic or text itself.
  • Stance Detection models the epistemic attitude or ideological orientation of the author (FAVOUR, AGAINST, or NONE) with respect to a predefined, fixed target proposition, regardless of whether that proposition is explicitly stated in the text.
Concrete Linguistic Example: Consider the comment: "यहाँ की भीषण गर्मी और बढ़ते प्रदूषण ने जीना हराम कर दिया है!" ("This extreme heat and rising pollution has made living unbearable!").
  • In Sentiment Analysis, this sentence receives a strongly NEGATIVE sentiment label due to grievance markers ("जीना हराम", "भीषण").
  • In Stance Detection with respect to the claim "Climate change is a serious concern", this sentence expresses unequivocal FAVOUR, as it highlights climate catastrophe as a grave human concern.
1.2 The Indic Script & Morphological Landscape Unlike English, which is weakly inflected and written in the Latin alphabet with simple whitespace tokenization boundaries, Hindi (Devanagari) and Bengali (Eastern Nagari / Bangla) are abugidas characterized by:
  • Akshara-Based Abugida Orthography: Consonants carry an inherent vowel (the schwa /a/). Vowels following consonants are written not as separate letters, but as combining diacritical marks called matras (e.g., ा, ि, ी, ु, ू).
  • Consonant Clusters (Yuktakshar / Samyuktakshar): Clusters of two or more consonants suppress the inherent vowel using a special virama (halant: ् in Hindi, ্ in Bengali) to form ligatures (e.g., क् + ष = क्ष).
  • Agglutinative Postpositional Inflection: Grammatical cases, tense, aspect, and honorific status are marked by inflecting verb stems and attaching postpositions (e.g., Hindi काट → काटना, काटने, काटा; Bengali কাট → কাটা, কাটলে, কাটবেন).

Without an algorithmic elongation ceiling, subword vocabularies explode with hapax legomena (single-occurrence words) that degrade statistical classifiers.

# CODE FOR STEP 2: Controlled Noise & Elongation Ceiling Injection
import random
import pandas as pd

def inject_controlled_noise(text, noise_level):
    if noise_level == "clean":
        return text
    
    chars = list(text)
    if noise_level == "light":
        # Add realistic terminal punctuation or emoji
        if random.random() < 0.3:
            chars.append(" ।")
        return "".join(chars)
        
    elif noise_level == "heavy":
        # Controlled character elongation (capped at max 3 repeats)
        elongated = []
        elongation_count = 0
        for ch in chars:
            elongated.append(ch)
            # Elongate vowels/consonants only if quota not exceeded
            if ch in "ाीूेैोौতদসশহ" and elongation_count < 2 and random.random() < 0.15:
                elongated.append(ch * 2)
                elongation_count += 1
        return "".join(elongated)

SECTION 4: STEP 3 — PREPROCESSING & INDIC NORMALIZATION

4.1 Theory: Unicode Equivalence & Canonical Composition

In Unicode standards, Indic scripts allow multiple distinct binary representations for identical graphemes:

  • NFD (Canonical Decomposition): Characters are decomposed into base glyph + combining diacritical mark (e.g., consonant + separate matra).
  • NFC (Canonical Composition): Characters are combined into a single precomposed Unicode codepoint.

Without unicodedata.normalize('NFC', text), two identical words typed on different operating systems evaluate as completely unequal byte arrays in Python.

4.2 Problems Faced in Step 3

Problem 3.1: Invisible Zero-Width Characters in Mobile Keyboards Android and iOS Indic virtual keyboards inject invisible zero-width formatting codes:
  • Zero-Width Space (\u200B)
  • Zero-Width Non-Break Space / BOM (\uFEFF)
  • Zero-Width Non-Joiner (\u200C, ZWNJ) & Zero-Width Joiner (\u200D, ZWJ)
While ZWJ is linguistically necessary for certain Bengali ligatures (e.g. র‍্য), random zero-width spaces break word equality: "जलवायु" vs "जल\u200Bवायु" look identical to humans, but fail string matching.
Problem 3.2: ASCII Pipe Confusion & Chandrabindu Mutilation Users routinely type the ASCII vertical pipe | instead of the authentic Indic danda (।, \u0964). Furthermore, crude text normalization packages often flatten the phonemic Chandrabindu (ँ, ঁ) into Anusvara (ं, ং), which alters the semantic meaning of Hindi words (e.g., हँसना [to laugh] vs हंस [swan]).

4.3 What We Did to Solve It

Engineered Solutions in src/preprocessing.py:
  1. Applied Unicode NFC canonical composition across all strings.
  2. Sanitized rogue zero-width spaces (\u200B, \uFEFF, \u00A0) while strictly protecting ligature-forming ZWJ sequences.
  3. Normalized mobile ASCII pipes (|) into authentic Indic dandas (।).
  4. Protected Chandrabindu as an independent phoneme distinct from Anusvara.
  5. Implemented selective de-elongation: squashed sequences of 3+ identical characters down to 2, preventing vocabulary inflation while preserving genuine geminate consonants (e.g., पक्का, দিল্লি).
  6. Padded emojis with whitespace so that tokenizers do not merge emojis with neighboring words.
# CODE FOR STEP 3: Complete Indic Preprocessing Engine
import re
import unicodedata

ZWJ = "\u200D"
ZWNJ = "\u200C"

def clean_indic_text(text):
    if not isinstance(text, str):
        return ""
    
    # 1. Unicode NFC Normalization
    text = unicodedata.normalize("NFC", text)
    
    # 2. Sanitize invisible zero-width characters (protecting ZWJ for ligatures)
    text = text.replace("\u200B", "").replace("\uFEFF", "").replace("\u00A0", " ")
    
    # 3. Mobile keyboard pipe to Indic Danda
    text = re.sub(r'\|+', ' । ', text)
    
    # 4. Strip URLs, HTML tags, and @mentions
    text = re.sub(r'http\S+|www\.\S+', '', text)
    text = re.sub(r'<.*?>', '', text)
    text = re.sub(r'@\w+', '', text)
    
    # 5. Selective De-elongation (Squash 3+ repeated characters to 2)
    # Preserves valid double consonants like पक्का, दिल्ली
    text = re.sub(r'(.)\1{2,}', r'\1\1', text)
    
    # 6. Emoji Spacing (Surround emojis with spaces to prevent word-boundary merger)
    emoji_regex = re.compile(r'([\U00010000-\U0010ffff\u2600-\u27bf])')
    text = emoji_regex.sub(r' \1 ', text)
    
    # 7. Normalize multi-whitespace
    text = re.sub(r'\s+', ' ', text).strip()
    return text
Empirical Result: Produced normalized, linguistically consistent text across both languages, saved to data/processed/.

5.1 Theory: Dual-Level Feature Spaces & Scikit-Learn Tokenizer Hazards

In text classification, statistical models map variable-length strings into fixed-length numeric vectors. However, applying off-the-shelf vectorizers to Indic text introduces fundamental linguistic failure modes:

5.2 Problems Faced in Step 4

Problem 4.1: Default Regex Shreds Indic Matras & Drops Emojis Scikit-Learn's default tokenization regex (?u)\b\w\w+\b assumes Latin word boundary semantics. In Indic scripts, \b separates vowel signs (matras) and consonant conjunct markers (viramas) from their base letters, corrupting word roots. Furthermore, it completely discards emojis (such as 🌱, 🌍, 🙄, 🤡), which are critical stance indicators.
Problem 4.2: Word-Level Sparsity & The Semantic Minimization Blindspot Word n-grams alone fail to capture shared morphological roots across dialectal inflections. Furthermore, bag-of-words models suffer from topical noun bias: in minimization sentences like "पेड़ काटने से कुछ नहीं होता, प्रकृति खुद सब संभाल लेती है" (Expected: AGAINST), the positive nouns ("पेड़", "प्रकृति") overwhelm the negation clause ("कुछ नहीं होता"), causing Naive Bayes to predict FAVOUR.

5.3 What We Did to Solve It

Engineered Solutions in src/baselines.py:
  1. Constructed indic_tokenize() with explicit Unicode ranges and passed token_pattern=None to override Scikit-Learn's destructive default.
  2. Engineered a FeatureUnion combining word n-grams (1–2) and character boundary subwords (2–4, char_wb), generating exactly 40,260 features with strict zero data leakage.
  3. Trained 4 diverse classifiers: Complement Naive Bayes (ComplementNB), Logistic Regression (Balanced L2), Linear SVC, and Random Forest (100 Trees).

SECTION 6: STEP 5 — CONTEXTUAL TRANSFORMER FINE-TUNING (GOOGLE MuRIL)

6.1 Theory: Deep Bidirectional Cross-Attention & Transfer Learning

Google MuRIL (google/muril-base-cased) employs a BERT-based transformer architecture with 12 layers, 768 hidden dimensions, and 12 attention heads. Unlike static n-gram models, MuRIL computes dynamic contextual representations: the vector for a word (e.g. "काटने") is conditioned on the entire left and right context, allowing it to capture long-range semantic dependencies and nuanced tone (such as sarcasm).

6.2 Problems Faced in Step 5

Problem 5.1: The MuRIL [UNK] Emoji Collapse Trap Pretrained MuRIL's WordPiece vocabulary of 197,285 tokens contains native Indic characters but zero modern emojis. Out-of-the-box, every emoji was mapped to token ID 1 ([UNK]), destroying sarcasm and sentiment cues.
Problem 5.2: Colab Runtime Version Crashes (KeyError & TypeError) During cloud fine-tuning, standard CSV column naming discrepancies caused KeyError: 'cleaned_text'. Furthermore, modern versions of HuggingFace transformers (v4.49+) threw TypeError when encountering deprecated parameters like logging_dir in TrainingArguments.
Problem 5.3: Local CPU Compute Bottleneck Local training across 110M parameters on Windows CPU required ~45 minutes per epoch with thermal throttling.

6.3 What We Did to Solve It

Engineered Solutions in src/transformers_train.py & Colab:
  1. Emoji Vocabulary Expansion: Extracted all unique emojis from the corpus, registered them via tokenizer.add_tokens(unique_emojis), and resized the embedding matrix via model.resize_token_embeddings(len(tokenizer)) from 197,285 to 197,297 rows.
  2. Robust Runtime Fallback: Added automatic column detection (text_col = 'cleaned_text' if 'cleaned_text' in df.columns else 'text') and updated TrainingArguments to modern syntax.
  3. GPU Acceleration: Executed fine-tuning on a Google Colab Tesla T4 GPU using AdamW ($lr=2\times 10^{-5}$, weight decay $0.01$, linear warmup scheduler), completing 3 epochs in under 3 minutes.
# CODE FOR STEP 5: Complete MuRIL Training & Evaluation Engine
import torch
import numpy as np
import pandas as pd
from torch.utils.data import Dataset, DataLoader
from transformers import AutoTokenizer, AutoModelForSequenceClassification, get_linear_schedule_with_warmup
from sklearn.metrics import classification_report, accuracy_score, f1_score

DEVICE = torch.device("cuda" if torch.cuda.is_available() else "cpu")
TARGET_CLASSES = ["AGAINST", "FAVOUR", "NONE"]
LABEL2ID = {label: idx for idx, label in enumerate(TARGET_CLASSES)}
ID2LABEL = {idx: label for idx, label in enumerate(TARGET_CLASSES)}

# 1. Dataset Wrapper
class IndicDataset(Dataset):
    def __init__(self, texts, labels, tokenizer, max_length=128):
        self.texts = list(texts)
        self.labels = [LABEL2ID[l] for l in labels]
        self.tokenizer = tokenizer
        self.max_length = max_length

    def __len__(self):
        return len(self.texts)

    def __getitem__(self, idx):
        encoding = self.tokenizer(str(self.texts[idx]), truncation=True, padding="max_length", max_length=self.max_length, return_tensors="pt")
        return {
            "input_ids": encoding["input_ids"].squeeze(0),
            "attention_mask": encoding["attention_mask"].squeeze(0),
            "labels": torch.tensor(self.labels[idx], dtype=torch.long)
        }

# 2. Tokenizer Expansion & Model Resizing
tokenizer = AutoTokenizer.from_pretrained("google/muril-base-cased")
model = AutoModelForSequenceClassification.from_pretrained("google/muril-base-cased", num_labels=3)

all_corpus_text = " ".join(train_df["cleaned_text"].tolist() + test_df["cleaned_text"].tolist())
unique_emojis = sorted(list(set(re.findall(r'[\U00010000-\U0010ffff\u2600-\u27bf]', all_corpus_text))))
num_added = tokenizer.add_tokens(unique_emojis)
if num_added > 0:
    model.resize_token_embeddings(len(tokenizer))
model.to(DEVICE)

# 3. DataLoaders & Optimization
train_loader = DataLoader(IndicDataset(train_df["cleaned_text"], train_df["stance"], tokenizer), batch_size=16, shuffle=True)
test_loader = DataLoader(IndicDataset(test_df["cleaned_text"], test_df["stance"], tokenizer), batch_size=16, shuffle=False)

optimizer = torch.optim.AdamW(model.parameters(), lr=2e-5, weight_decay=0.01)
total_steps = len(train_loader) * 3
scheduler = get_linear_schedule_with_warmup(optimizer, num_warmup_steps=int(total_steps * 0.1), num_training_steps=total_steps)

# 4. Training Loop (3 Epochs)
for epoch in range(1, 4):
    model.train()
    total_loss = 0.0
    for batch in train_loader:
        optimizer.zero_grad()
        loss = model(batch["input_ids"].to(DEVICE), attention_mask=batch["attention_mask"].to(DEVICE), labels=batch["labels"].to(DEVICE)).loss
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        optimizer.step()
        scheduler.step()
        total_loss += loss.item()
    print(f"Epoch {epoch} Completed | Average Loss: {total_loss/len(train_loader):.4f}")

# 5. Final Test Evaluation (320 Samples)
model.eval()
test_preds, test_labels = [], []
with torch.no_grad():
    for batch in test_loader:
        logits = model(batch["input_ids"].to(DEVICE), attention_mask=batch["attention_mask"].to(DEVICE)).logits
        test_preds.extend(torch.argmax(logits, dim=-1).cpu().numpy())
        test_labels.extend(batch["labels"].numpy())

print(classification_report(test_labels, test_preds, target_names=TARGET_CLASSES, digits=4))
