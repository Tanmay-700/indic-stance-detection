Step 4: Classical Machine Learning Baselines

In Step 4, our goal was to establish strong statistical baselines using sparse feature engineering. We designed a dual-level TF-IDF representation coupled with four distinct learning algorithms evaluated strictly under zero data leakage conditions.

1. The Critical Scikit-Learn Regex Hazard

Standard scikit-learn tokenizers use the default regular expression (?u)\b\w\w+\b. When applied to Devanagari or Bengali scripts, this regex violently shreds Indic matras (vowel signs), viramas (halant ्, ্), and discards all standalone emojis.

Engineered Fix: Custom Indic Regex Tokenizer We engineered indic_tokenize() in src/preprocessing.py using custom Unicode character classes and grapheme cluster definitions. We explicitly instantiated vectorizers with: TfidfVectorizer(tokenizer=indic_tokenize, token_pattern=None).

2. Dual-Level TF-IDF Feature Engineering

We used a FeatureUnion combining two complementary granularities:

  • Word N-grams (1–2): Captures full semantic terms, multi-word phrases (e.g., "ग्लोबल वार्मिंग", "জলবায়ু পরিবর্তন"), and emoji grapheme clusters.
  • Character Subwords (2–4, char_wb): Captures morphological roots, postpositions, and inflections across dialectal variations without requiring a full morphological lemmatizer.
# Implementation Snippet: Dual-Level FeatureUnion (Zero Data Leakage)
from sklearn.pipeline import FeatureUnion
from sklearn.feature_extraction.text import TfidfVectorizer
from src.preprocessing import indic_tokenize

word_vectorizer = TfidfVectorizer(
    tokenizer=indic_tokenize,
    token_pattern=None,
    ngram_range=(1, 2),
    min_df=2,
    sublinear_tf=True
)

char_vectorizer = TfidfVectorizer(
    analyzer="char_wb",
    ngram_range=(2, 4),
    min_df=2,
    sublinear_tf=True
)

tfidf_union = FeatureUnion([
    ("word_features", word_vectorizer),
    ("char_features", char_vectorizer)
])

# Fitted STRICTLY on Train split (2,560 rows) -> Yielding exactly 40,260 features
X_train = tfidf_union.fit_transform(train_df["cleaned_text"])
X_test  = tfidf_union.transform(test_df["cleaned_text"])

3. Evaluated Classical Classifiers

Complement Naive Bayes (ComplementNB)

Designed specifically for text classification with imbalanced distributions. Estimates parameters from the complement of each class, countering sparsity and document length discrepancies.

Result: Champion Baseline (100% Test Accuracy, 1.0000 Macro F1).

Logistic Regression (Balanced L2)

Maximum-entropy linear classifier using balanced class weights and liblinear/lbfgs solver. Provides calibrated posterior probabilities.

Result: 100% Test Accuracy, 1.0000 Macro F1.

Linear Support Vector Classifier (LinearSVC)

Maximizes the geometric margin between stance hyperplanes. Very effective in ultra-high dimensional sparse feature spaces (40k+ features).

Key Discovery from Step 4 Error Analysis: Semantic Minimization While in-sample test performance was 100%, stress-testing on out-of-domain subtle sentences exposed a critical blindspot in bag-of-words models: "पेड़ काटने से कुछ नहीं होता, प्रकृति खुद सब संभाल लेती है" (Expected: AGAINST). Naive Bayes predicted FAVOUR because the individual words "पेड़" (tree) and "प्रकृति" (nature) carry overwhelming positive environmental frequency, blinding the model to the negation clause "कुछ नहीं होता". This directly motivated Step 5 (Transformer Attention).

Step 5: Contextual Transformer Fine-Tuning (Google MuRIL)

In Step 5, we addressed the limitation of surface n-grams by fine-tuning Google MuRIL (Multilingual Representations for Indic Languages). MuRIL is a BERT-based transformer pretrained on 17 Indic languages and English using both monolingual and translated/transliterated parallel corpora.

1. The MuRIL [UNK] Emoji Trap & Custom Tokenizer Expansion

Social media comments convey critical stance through emojis (e.g., 🌱 indicates pro-environmental action, while 🙄 and 🤡 indicate mockery and denial).

The Problem: MuRIL's base vocabulary contains 197,285 WordPiece tokens covering Indic scripts, but zero contemporary emojis! Out-of-the-box, MuRIL collapses every single emoji into the generic [UNK] token (ID 1), stripping vital stance cues. 

# Engineered Fix: Custom Emoji Vocabulary Expansion (Step 5 Core Innovation)
import re
from transformers import AutoTokenizer, AutoModelForSequenceClassification

MODEL_NAME = "google/muril-base-cased"
tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)

# 1. Scan corpus for all unique emoji grapheme clusters
emoji_pattern = re.compile(r'[\U00010000-\U0010ffff\u2600-\u27bf]')
all_corpus_texts = train_df['cleaned_text'].tolist() + test_df['cleaned_text'].tolist()
unique_emojis = sorted(list(set(emoji_pattern.findall(" ".join(all_corpus_texts)))))

# 2. Add tokens to vocabulary so they NEVER map to [UNK]
num_added = tokenizer.add_tokens(unique_emojis)
print(f"Added {num_added} unique emojis! New Vocab Size: {len(tokenizer):,d}")

# 3. Resize model token embedding matrix to learn dedicated 768-dim embeddings
model = AutoModelForSequenceClassification.from_pretrained(MODEL_NAME, num_labels=3)
model.resize_token_embeddings(len(tokenizer))

2. Fine-Tuning Hyperparameters & Training Execution

Because local CPU training would require ~45 minutes per epoch, we engineered the turnkey pipeline in src/transformers_train.py and executed training using a Tesla T4 GPU on Google Colab:

Training Configuration

  • Base Architecture: google/muril-base-cased (12 layers, 768 hidden, 12 attention heads)
  • Sequence Length: Max 128 tokens (covers 100% of corpus without truncating sentiment)
  • Batch Size: 16 per device
  • Optimization: AdamW ($lr = 2 \times 10^{-5}$, weight decay = $0.01$)

Regularization & Checkpointing

  • Learning Rate Warmup: Linear scheduler over initial 10% of total training steps
  • Gradient Clipping: Max norm = 1.0
  • Epochs: 3 epochs (~160 steps/epoch, 480 total optimizer steps)
  • Model Selection: Checkpoint evaluated on Validation Macro F1 at each epoch
