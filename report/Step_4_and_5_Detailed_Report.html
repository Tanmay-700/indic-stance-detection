SECTION 1: THEORETICAL FOUNDATIONS OF STANCE DETECTION

1.1 Stance Detection vs. Sentiment Analysis Stance classification determines whether an author is in agreement with, opposition to, or neutral towards a fixed proposition (“Climate change is a serious concern”), irrespective of whether that proposition is explicitly stated in the post.
  • Sentiment reflects subjective emotional valence (positive, negative, or neutral).
  • Stance reflects propositional loyalty or ideological orientation.
Illustrative Example: “भीषण गर्मी और सूखे ने किसानों की कमर तोड़ दी है 😢” (“Extreme heat and drought have broken the farmers' backs 😢”).
In sentiment analysis, this sentence is strongly Negative. However, regarding the proposition that climate change is an alarming reality, the comment is unequivocal FAVOUR.
1.2 Indic Abugida Orthography & Linguistic Characteristics Hindi (Devanagari) and Bengali (Eastern Nagari) are not alphabets; they are abugidas:
  • Every consonant possesses an inherent schwa vowel (/a/). Non-inherent vowels are written as combining vowel diacritics called matras (e.g. ा, ि, ী, ু).
  • Suppression of the inherent vowel in consonant clusters is denoted by the halant / virama (् in Hindi, ্ in Bengali), creating ligatures (Yuktakshar).
  • Bengali and Hindi are morphologically agglutinative: verbs and nouns inflect heavily via bound morphemes and postpositions (e.g., Hindi काट → काटने, काटेंगे; Bengali কাট → কাটা, কাটলে).

SECTION 3: STEP 2 — CORPUS DESIGN & CONTROLLED NOISE MODELING

3.1 The Problem Faced

Problem 2.1: The Silent Pandas NaN Label Corruption When reading CSV datasets with pandas (pd.read_csv()), strings matching "none" or "NONE" are by default treated as missing values (np.nan). This silently casts string label columns into mixed object/float types, throwing ValueError: mixed data types during model fitting.
Problem 2.2: Uncontrolled Elongation & Subword Explosion Social media character elongation (e.g., "झूठठठठठ") causes an explosive expansion of unique subwords, creating severe data sparsity if left unconstrained.

3.2 What We Did to Solve It

Engineered Solutions in src/collect_and_curate_data.py:
  1. Standardized class labels strictly in uppercase: FAVOUR, AGAINST, NONE, and enforced pd.read_csv(..., keep_default_na=False).
  2. Curated 440 unique handcrafted seeds across 11 balanced subcategories (220 Hindi + 220 Bengali; 20 per subcategory).
  3. Built an algorithmic multi-tier noise generator locked to:
    • 35% Clean: Standard grammatical text.
    • 50% Light Noise: 1–2 emojis, common keyboard typos, Indic dandas.
    • 15% Heavy Noise: Punctuation clusters, character elongation (strictly capped at ~3.75%).
  4. Generated exactly 3,200 stratified samples (1,600 Hindi, 1,600 Bengali): Train (2,560), Val (320), Test (320), Hidden Test (320).
src/collect_and_curate_data.py (Controlled Noise Engine) Python 
import random
import pandas as pd

def apply_controlled_noise(text, tier):
    if tier == "clean":
        return text
    
    chars = list(text)
    if tier == "light":
        # Inject danda or minor keyboard variation
        if random.random() < 0.3:
            chars.append(" ।")
        return "".join(chars)
        
    elif tier == "heavy":
        # Strict elongation ceiling (capped at max 2 repeats to prevent vocabulary explosion)
        elongated = []
        elongations_done = 0
        for c in chars:
            elongated.append(c)
            if c in "ाीूेैोौতদসশহ" and elongations_done < 2 and random.random() < 0.12:
                elongated.append(c * 2)
                elongations_done += 1
        return "".join(elongated)

SECTION 4: STEP 3 — PREPROCESSING & INDIC NORMALIZATION

4.1 The Problem Faced

Problem 3.1: Invisible Zero-Width Characters Breaking String Equivalence Mobile Indic keyboards insert invisible zero-width characters:
  • Zero-Width Space (\u200B) and Zero-Width Non-Break Space (\uFEFF)
  • Zero-Width Joiner (\u200D, ZWJ) and Zero-Width Non-Joiner (\u200C, ZWNJ)
A string like "जलवायु" and "जल\u200Bवायु" look identical to human evaluators, but in Python evaluate to False under string equality, creating duplicated vocabulary entries.
Problem 3.2: Mobile Pipe | & Chandrabindu Flattening Users frequently type the ASCII vertical pipe | instead of the authentic Indic danda (।). Furthermore, naive NLP cleaners often flatten Chandrabindu (ँ, ঁ) into Anusvara (ं, ং), which alters word meanings (e.g., हँसना [to laugh] vs हंस [swan]).

4.2 What We Did to Solve It

Engineered Solutions in src/preprocessing.py:
  1. Enforced Unicode NFC canonical composition.
  2. Stripped zero-width spaces (\u200B, \uFEFF, \u00A0) while protecting ligature-forming ZWJs in Bengali.
  3. Replaced ASCII pipes (|) with authentic dandas (।).
  4. Preserved Chandrabindu as an independent phoneme.
  5. Squashed sequences of 3+ identical characters down to 2, preserving genuine double consonants (gemination: e.g. पक्का, দিল্লি).
  6. Surrounded emojis with whitespace so tokenizers never merge an emoji with an adjacent word.
src/preprocessing.py Python 
import re
import unicodedata

def clean_indic_text(text):
    if not isinstance(text, str):
        return ""
    
    # 1. Unicode NFC Normalization (canonical composition)
    text = unicodedata.normalize("NFC", text)
    
    # 2. Sanitize invisible zero-width formatting codes (preserve ZWJ for ligatures)
    text = text.replace("\u200B", "").replace("\uFEFF", "").replace("\u00A0", " ")
    
    # 3. Mobile keyboard pipe to authentic Indic Danda
    text = re.sub(r'\|+', ' । ', text)
    
    # 4. Strip URLs, HTML tags, and user mentions
    text = re.sub(r'http\S+|www\.\S+', '', text)
    text = re.sub(r'<.*?>', '', text)
    text = re.sub(r'@\w+', '', text)
    
    # 5. Selective De-elongation (Squash 3+ repeats to 2; protects geminates like पक्का, দিল্লি)
    text = re.sub(r'(.)\1{2,}', r'\1\1', text)
    
    # 6. Emoji Spacing (Padding emojis to prevent merging with surrounding words)
    emoji_pattern = re.compile(r'([\U00010000-\U0010ffff\u2600-\u27bf])')
    text = emoji_pattern.sub(r' \1 ', text)
    
    # 7. Normalize multi-whitespace
    text = re.sub(r'\s+', ' ', text).strip()
    return text
Empirical Result: Datasets normalized and stored in data/processed/ with uniform token boundaries.

SECTION 5: STEP 4 — CLASSICAL ML BASELINES & EMOJI VECTORIZATION

5.1 Deep Technical Theory: How Classical Models Process and Recognize Emojis

Theory of Classical Emoji Representation: In statistical NLP, classical models (ComplementNB, Logistic Regression, LinearSVC, Random Forest) cannot read raw text directly. They operate on a high-dimensional vector space $\mathbb{R}^{|V|}$.

1. Emoji Recognition: Emojis exist in the 4-byte Supplementary Multilingual Plane (SMP, codepoints U+1F000 to U+10FFFF). Our custom tokenizer regex explicitly defines an SMP match group: $$\text{SMP\_PATTERN} = [\backslash\text{U00010000}-\backslash\text{U0010ffff}]$$ When the tokenizer encounters 🌱 (\U0001F331) or 🤡 (\U0001F921), it extracts them as atomic string tokens.

2. Emoji Vectorization (Term Frequency - Inverse Document Frequency): Each unique emoji is assigned a dedicated feature index in the 40,260-dimensional TF-IDF matrix. For document $d$ and emoji $t$: $$\text{TF-IDF}(t, d) = (1 + \log(\text{TF}(t, d))) \times \log\left(\frac{1 + N}{1 + \text{DF}(t)}\right)$$ 3. Model Learning:
  • In Logistic Regression, each emoji gets a learned weight $w_{c, t}$. For example, $w_{\text{FAVOUR}, 🌱} > 0$ and $w_{\text{AGAINST}, 🤡} > 0$.
  • In Complement Naive Bayes, parameter $\theta_{c, t}$ represents the likelihood of seeing emoji $t$ in all documents not in class $c$. Emojis exclusive to denial (🤡, 🙄) receive low complement likelihood, boosting posterior odds for AGAINST.

5.2 The Problem Faced

Problem 4.1: Scikit-Learn Default Regex Deletes All Emojis Scikit-Learn's default tokenization regex (?u)\b\w\w+\b matches only alphanumeric word characters. It treats Unicode emojis as punctuation, deleting every single emoji during vectorization. Furthermore, \b breaks Indic matras from base consonants.
Problem 4.2: Semantic Minimization Blindspot In sentences like "पेड़ काटने से कुछ नहीं होता, प्रकृति खुद सब संभाल लेती है" (Expected: AGAINST), the environmental nouns "पेड़" and "प्रकृति" carry high statistical weights for FAVOUR, overpowering the negation clause "कुछ नहीं होता".

5.3 What We Did to Solve It

Engineered Solutions in src/baselines.py:
  1. Constructed indic_tokenize() with explicit Unicode character and emoji ranges, and passed token_pattern=None to Scikit-Learn.
  2. Built a dual-level FeatureUnion combining word n-grams (1–2) with character subwords (2–4, char_wb), generating 40,260 features with strict zero data leakage.
  3. Trained ComplementNB, Logistic Regression (Balanced L2), LinearSVC, and Random Forest.
src/baselines.py (Complete Classical ML Pipeline) Python 
import re
import pandas as pd
from sklearn.pipeline import FeatureUnion
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.naive_bayes import ComplementNB
from sklearn.linear_model import LogisticRegression
from sklearn.svm import LinearSVC
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import accuracy_score, f1_score, classification_report

# Custom Tokenizer that explicitly matches Indic words, matras, and emojis
INDIC_PATTERN = re.compile(
    r'[\u0900-\u097F]+|'            # Devanagari (Hindi)
    r'[\u0980-\u09FF]+|'            # Bengali (Bangla)
    r'[\U00010000-\U0010ffff]|'     # 4-byte SMP Emojis (🌱, 🌍, 🤡, 😂)
    r'[\u2600-\u27bf]|'             # Standard Unicode symbols (⚠️, ☀️)
    r'[0-9]+|'                      # Digits
    r'[^\s\w]'                      # Punctuation (। , ! ?)
)

def indic_tokenize(text):
    return INDIC_PATTERN.findall(text) if isinstance(text, str) else []

# Dual-level TF-IDF (Zero Data Leakage: fitted strictly on Train split)
word_vec = TfidfVectorizer(tokenizer=indic_tokenize, token_pattern=None, ngram_range=(1, 2), min_df=2, sublinear_tf=True)
char_vec = TfidfVectorizer(analyzer="char_wb", ngram_range=(2, 4), min_df=2, sublinear_tf=True)
tfidf_union = FeatureUnion([("word", word_vec), ("char", char_vec)])

train_df = pd.read_csv("data/processed/train.csv")
test_df  = pd.read_csv("data/processed/test.csv")

X_train = tfidf_union.fit_transform(train_df["cleaned_text"])
y_train = train_df["stance"].values
X_test  = tfidf_union.transform(test_df["cleaned_text"])
y_test  = test_df["stance"].values

# Fit Classical ML Models
clf_cnb = ComplementNB(alpha=0.5, norm=True).fit(X_train, y_train)
clf_lr  = LogisticRegression(C=1.0, max_iter=1000, class_weight="balanced", random_state=42).fit(X_train, y_train)
clf_svc = LinearSVC(C=1.0, class_weight="balanced", random_state=42).fit(X_train, y_train)
clf_rf  = RandomForestClassifier(n_estimators=100, class_weight="balanced", random_state=42).fit(X_train, y_train)

# Evaluate on Test Set
for name, clf in [("ComplementNB", clf_cnb), ("LogisticRegression", clf_lr), ("LinearSVC", clf_svc), ("RandomForest", clf_rf)]:
    preds = clf.predict(X_test)
    print(f"{name:20s} | Accuracy: {accuracy_score(y_test, preds)*100:.2f}% | Macro F1: {f1_score(y_test, preds, average='macro'):.4f}")

SECTION 6: STEP 5 — TRANSFORMER (MuRIL) & EMOJI EMBEDDING MECHANICS

6.1 Deep Technical Theory: How Transformers Process, Recognize & Learn Emojis

Theory of Transformer Attention Over Emojis: Unlike classical bag-of-words models, Google MuRIL represents language as a sequence of dense vectors processed through 12 Multi-Head Self-Attention layers:

1. The Subword Tokenization Phase: MuRIL uses WordPiece. When a sentence is parsed: $$\text{Sentence} \xrightarrow{\text{WordPiece}} [t_1, t_2, \dots, t_n]$$ If an emoji (e.g. 🌱) is not in the model's vocabulary, WordPiece maps it to token ID 1 ([UNK]).

2. Embedding Matrix Resizing Mechanics: MuRIL's initial embedding table is $E \in \mathbb{R}^{197285 \times 768}$. By adding $K$ discovered unique emojis via tokenizer.add_tokens(unique_emojis) and calling model.resize_token_embeddings(): $$E_{\text{new}} \in \mathbb{R}^{(197285 + K) \times 768} = \mathbb{R}^{197297 \times 768}$$ Each newly added emoji token $t_{\text{emoji}}$ is assigned a dedicated row in the embedding matrix, initialized from $\mathcal{N}(0, 0.02)$.

3. Bidirectional Contextual Attention During Training: During forward propagation, the emoji vector $x_{\text{emoji}} \in \mathbb{R}^{768}$ is projected into Query, Key, and Value matrices: $$Q = X W_Q, \quad K = X W_K, \quad V = X W_V$$ The attention score between word token $i$ (e.g., "मूड स्विंग") and emoji token $j$ (😂) is: $$\text{Attention}(i, j) = \text{softmax}\left(\frac{Q_i K_j^T}{\sqrt{d_k}}\right)$$ In backpropagation, cross-entropy gradients flow back through the attention weights directly into the emoji embedding row $E_{\text{new}}[t_{\text{emoji}}]$: $$\Delta E_{\text{new}}[t_{\text{emoji}}] = -\eta \frac{\partial \mathcal{L}_{\text{CE}}}{\partial E_{\text{new}}[t_{\text{emoji}}]}$$ This forces the embedding vector for 😂 to encode humorous skepticism, while 🌱 moves towards ecological urgency.

6.2 The Problem Faced

Problem 5.1: The MuRIL [UNK] Collapse Trap Pretrained MuRIL's 197,285-token vocabulary contains native Indic characters but zero modern emojis. Out-of-the-box, every emoji was mapped to token ID 1 ([UNK]). As a result, the transformer could not differentiate between sarcasm 😂, concern 🌱, or denial 🤡.
Problem 5.2: Colab Runtime Version Crashes (KeyError & TypeError) During cloud fine-tuning, column naming differences caused KeyError: 'cleaned_text'. Furthermore, modern versions of HuggingFace transformers (v4.49+) threw TypeError when encountering deprecated parameters like logging_dir in TrainingArguments.
Problem 5.3: Local CPU Compute Bottleneck Local training across 110M parameters on Windows CPU required ~45 minutes per epoch with thermal throttling.

6.3 What We Did to Solve It

Engineered Solutions in src/transformers_train.py & Colab:
  1. Emoji Vocabulary Expansion: Extracted all unique emojis from the corpus, registered them via tokenizer.add_tokens(unique_emojis), and resized the embedding matrix via model.resize_token_embeddings(len(tokenizer)) from 197,285 to 197,297 rows.
  2. Robust Runtime Fallback: Added automatic column detection (text_col = 'cleaned_text' if 'cleaned_text' in df.columns else 'text') and updated TrainingArguments to modern syntax.
  3. GPU Acceleration: Executed fine-tuning on a Google Colab Tesla T4 GPU using AdamW ($lr=2\times 10^{-5}$, weight decay $0.01$, linear warmup scheduler), completing 3 epochs in under 3 minutes.
src/transformers_train.py (Complete MuRIL PyTorch Pipeline) Python 
import re
import torch
import numpy as np
import pandas as pd
from torch.utils.data import Dataset, DataLoader
from transformers import AutoTokenizer, AutoModelForSequenceClassification, get_linear_schedule_with_warmup
from sklearn.metrics import classification_report, accuracy_score, f1_score

DEVICE = torch.device("cuda" if torch.cuda.is_available() else "cpu")
TARGET_CLASSES = ["AGAINST", "FAVOUR", "NONE"]
LABEL2ID = {l: i for i, l in enumerate(TARGET_CLASSES)}
ID2LABEL = {i: l for i, l in enumerate(TARGET_CLASSES)}

# 1. Custom PyTorch Dataset Wrapper
class IndicDataset(Dataset):
    def __init__(self, texts, labels, tokenizer, max_length=128):
        self.texts = list(texts)
        self.labels = [LABEL2ID[l] for l in labels]
        self.tokenizer = tokenizer
        self.max_length = max_length

    def __len__(self):
        return len(self.texts)

    def __getitem__(self, idx):
        enc = self.tokenizer(
            str(self.texts[idx]),
            truncation=True,
            padding="max_length",
            max_length=self.max_length,
            return_tensors="pt"
        )
        return {
            "input_ids": enc["input_ids"].squeeze(0),
            "attention_mask": enc["attention_mask"].squeeze(0),
            "labels": torch.tensor(self.labels[idx], dtype=torch.long)
        }

# 2. Tokenizer Expansion & Model Resizing Pipeline
MODEL_NAME = "google/muril-base-cased"
tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)
model = AutoModelForSequenceClassification.from_pretrained(MODEL_NAME, num_labels=3)

train_df = pd.read_csv("data/processed/train.csv")
test_df  = pd.read_csv("data/processed/test.csv")

# Discover emojis across the corpus
all_text = " ".join(train_df["cleaned_text"].tolist() + test_df["cleaned_text"].tolist())
unique_emojis = sorted(list(set(re.findall(r'[\U00010000-\U0010ffff\u2600-\u27bf]', all_text))))

# Add emojis into MuRIL vocabulary and expand embedding table
num_added = tokenizer.add_tokens(unique_emojis)
if num_added > 0:
    model.resize_token_embeddings(len(tokenizer))
    print(f"Added {num_added} emojis! New Vocab Size: {len(tokenizer):,d}")

model.to(DEVICE)

# 3. DataLoaders
train_loader = DataLoader(IndicDataset(train_df["cleaned_text"], train_df["stance"], tokenizer), batch_size=16, shuffle=True)
test_loader  = DataLoader(IndicDataset(test_df["cleaned_text"], test_df["stance"], tokenizer), batch_size=16, shuffle=False)

# 4. Optimization Engine
optimizer = torch.optim.AdamW(model.parameters(), lr=2e-5, weight_decay=0.01)
total_steps = len(train_loader) * 3
scheduler = get_linear_schedule_with_warmup(optimizer, num_warmup_steps=int(total_steps * 0.1), num_training_steps=total_steps)

# 5. Training Loop (3 Epochs on GPU)
for epoch in range(1, 4):
    model.train()
    total_loss = 0.0
    for batch in train_loader:
        optimizer.zero_grad()
        loss = model(batch["input_ids"].to(DEVICE), attention_mask=batch["attention_mask"].to(DEVICE), labels=batch["labels"].to(DEVICE)).loss
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        optimizer.step()
        scheduler.step()
        total_loss += loss.item()
    print(f"Epoch {epoch} Completed | Loss: {total_loss / len(train_loader):.4f}")

# 6. Final Test Evaluation (320 Samples)
model.eval()
test_preds, test_labels = [], []
with torch.no_grad():
    for batch in test_loader:
        logits = model(batch["input_ids"].to(DEVICE), attention_mask=batch["attention_mask"].to(DEVICE)).logits
        test_preds.extend(torch.argmax(logits, dim=-1).cpu().numpy())
        test_labels.extend(batch["labels"].numpy())

print(classification_report(test_labels, test_preds, target_names=TARGET_CLASSES, digits=4))
